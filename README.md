# ネーム刺繍ナビ（name-shishu.com）

作業着・ユニフォームに社名やロゴを入れたい人が、**持ち込みで受けてくれる刺繍の加工屋**と
**名入れごと頼める作業服店**を地域から探せる媒体。

## なぜ作るか

収益の柱は掲載料ではなく、**刺繍台帳（TandI）とカタログ台帳（CataBase）への送客**。
載せる加工屋がそのまま見込み客になる。掲載料と広告は並走させるが柱にしない
（刺しゅう業は全国1,513事業所しかなく、掲載課金だけでは規模が出ない）。
**無料掲載は、こちらが公式サイトで確認できた内容だけ**（2026-09-29 に本人が決定）。
こちらから掲載先へ知らせて条件を取材することはしない。
**掲載先から「これも載せてほしい」と問い合わせが来たら、年間の有料掲載（年9,800円・税込）で案内する** ――
写真・紹介文・市区ページの PR 枠に加えて、**「確認中」を埋める事実（納期・郵送・データ代・住所など）の追加もこちら**。
**誤りの訂正と掲載の削除だけは無料のまま**（利用規約 第4節で約束している。有料にすると
「誤りを載せて直すのに金を取る」形になる）。
（9/28 は「事実は無料・見せ方は有料」で、事実の追加も無料で受けていた。**78件への掲載の知らせ（取材）を
止めた**ので、無料で事実を集める経路が無くなり、線を「こちらが確認したもの／掲載先が足すもの」に引き直した。
基本掲載そのものは無料のまま ―― **払った店しか並ばない名簿にすると、比べられることという売りが崩れる**。
広告1本に絞る案も、月1万PVで月1〜3万円・通販広告が掲載店と食い合うので採らない）

判定日は 2026-10-31（母数）と 2027-03-31（読者数・問い合わせ・掲載先）。

## 中身の価値

**持ち込みの可否・最小枚数・納期・料金の目安**。この4つは Google マップにも各社サイトにも
横並びでは載っていない。**掲載の打診がそのまま取材になる**ので、返事が来るたびに埋まっていく。
**推測では書かない。** 確認が取れていない項目は「確認中」と出す。

## UI と UX の決めごと

**一覧は「カード」ではなく「比較行」。** 持ち込み・最小枚数・納期・料金を横に並べる。
縦にカードを積むと、売りである「比べられること」が成立しない。820px 以下では
ラベル付きの2列に畳む。

**絞り込みも「もっと見る」も DOM を hidden にするだけ。** React で行を作り直さない。
サーバーが描いた全件の HTML をそのまま残すため（JS を実行しないクローラーに全件読ませる）。
一度に出すのは20件で、残りは `hidden` を付けて隠してあるだけ。
**表示する行を決める場所は `app/Filter.tsx` の1か所**（絞り込みと件数制限を分けると互いを打ち消す）。
ボタンは一覧の下の `#more-slot` へ portal で出す ― 静的HTMLでは空のまま。

**確認できていない項目は「確認中」と出し、推測では書かない。**
構造化データにも載せない。空欄の各社ページには、情報提供への導線を置く。

**色は地が白、テーマ色は糸の緑、文字は濃紺。** 罫線ではなく面と余白で区切る。
変えるときは `app/globals.css` の `--accent` 系だけ触る（2026-09-17 に朱→青→緑）。

**トップはランディング、中身は下に全部残す。** ヒーロー → 品目 → 悩み → エリア →
条件がそろっている店 → **全件の比較行** → 読み物 → ABOUT → 帯。
モックに無くても**全件の HTML をトップから外さない**（AI クローラーに読ませるため）。

**「掲載は無料」とは画面に書かない**（2026-09-17）。**営業文では書く**（2026-09-28・本人の指定）：
「無料で掲載している／基本情報の追加・修正は無料／写真・紹介文・PR枠は有料で案内」を1段落で。
金額は初回に書かず、**「優先表示」とも書かない**（下の「掲載の順番は料金によって変わらない」と食い違う）。
画面に書くのは「掲載の順番は料金によって変わらない」まで ― 順位の公正は別の約束で、
有料掲載を始めても守れる。

**お気に入りはブラウザにだけ残す。** `localStorage` の `ns-fav`。
サーバーへは送らず、会員登録も持たない。プライバシーポリシーの第2節に書いてある。

**都道府県は画面に出すときだけ正式名にする**（`prefLabel()`）。
データは「東京」までしか持っていない。**slug は変えない** ― 配布済みの URL が変わる。

## 作り

- Next.js（App Router）の**静的書き出し**（`output: 'export'`）。全ページが素のHTML
- **データの正は掲載 DB（Turso `name-shishu`）。** 2026-09-29 に hp/001 の営業台帳（prospects）から分けた。
  **公開してよいものだけを入れる DB** で、営業のメモ・メールアドレス・送信履歴は1列も無い
- **サイトは DB に繋がない。** ビルドは `data/*.json` を読むだけで、Vercel に接続情報を置かない。
  DB を触るのは手元の `scripts/` と `db/` だけ（接続情報は `.env.local`・`.gitignore` 済み）
- AIクローラーは JS を実行しないので、一覧も各社ページもサーバー側で描き切る

## データの更新

```bash
node scripts/export.mjs --write   # 掲載 DB → data/listings.json・plans.json・photos.json（**ビルドの前に必ず**）
npm run build                     # → push で Vercel が本番に出す
# デプロイが終わってから
node scripts/indexnow.mjs --send  # 本文が変わったページと新しいページだけ Bing へ知らせる
git add .indexnow-state.json && git commit -m "IndexNow 送信"   # 送った状態を残す（次の差分の基準）
```

**IndexNow（2026-09-29〜）**：Bing（＝ChatGPT・Copilot が引くインデックス）へ URL を知らせる仕組み。
Google の URL 検査（1日10件）と違って上限が実質無い。**Google は IndexNow を使わない**ので、Google はサイトマップと URL 検査のまま。
鍵は `public/<32桁>.txt`（秘密ではない。消すと送れなくなる）。**デプロイ前に流すと、Bing が古い版を読む**ので順番を守る。
毎回全ページを送らない（`--all` は普段使わない）― 変わっていないのに送り続けると信用の低い送り方になる。

### 店を足す

加工屋を探すのは hp/001 側（`places.mjs` で検索 → サイトを読んで精査）。精査が済んだものをここに入れる。

```bash
node scripts/add.mjs --json <候補.json> --dry-run   # places.mjs の「追記用」＋ place_id
node scripts/add.mjs --json <候補.json>
node scripts/verify.mjs --apply                     # 公式サイトで住所と電話を取り直す
node scripts/scan-terms.mjs --since <時刻> --full   # 4項目を拾う。**根拠を読んでから** --apply
```

- **営業台帳とは別物。** ここに足しても営業の対象にはならないし、営業で見送りにしても掲載は消えない。
  2つは `place_id`（Places の規約で無期限に保存してよい唯一の項目）でつながるだけ
- **Places の住所・電話は `hint_addr` / `hint_tel` に一時的に入る。** 公式サイトの住所と突き合わせるためだけで、
  書き出さない。裏取りが済んだら `verify.mjs` が消す
- **`scan-terms.mjs --apply` は空の項目だけ埋める。** 手で直した値は上書きしない（`--overwrite` のときだけ上書き）
- **誤読を見つけたら、根拠の頭に「【採用しない：理由】」を付けて値を空にする。** 空にしただけだと
  「まだ調べていない」と区別できず、次の `--apply` で同じ誤読が戻る（2026-09-29 に実際に戻った）
- **掲載をやめるときは消さずに `status='非掲載'`**（`hide_reason` に理由）。消すと次の検索でまた拾う
- 列を足すときは「サイトに出してよいか」を先に決める。`scripts/export.mjs` が書き出す列だけが公開される

## 手元で見る

```bash
npm run dev     # http://localhost:3000
```

**dev が動いている間に `npm run build` を流さない。** どちらも `.next` を使うので、
本番ビルドが dev の中間ファイルを上書きして 500 になる（2026-09-17 に踏んだ）。
壊れたら `pkill -f "next dev" && rm -rf .next` で入れ直す。
確認は dev で足り、デプロイは push すれば Vercel 側でビルドされる。

**直したものが出ないときは数秒待つ。** ホットリロードが追いつく前に見ると前の版が返る。

**push の前に `npx tsc --noEmit` を流す。** `next dev` は型を見ないので、dev で動いていても
本番ビルドが型エラーで落ちる（2026-09-17 に4回連続で落とした）。
`tsc --noEmit` は `.next` を触らないので dev を動かしたまま流せる。

## OGP画像（SNSに貼ったときのカード）

**`public/ogp.png` が配信される本体。SVG は貼っても画像が出ない。**
X・Facebook・LINE・LinkedIn のどれも `og:image` の SVG を読まない（2026-09-18 に
LinkedIn でカードが出ないことで判明。UNIX は PNG なので出ていた）。

正は `public/ogp.svg`。**テーマ色や文言を変えたら SVG を直し、PNG を起こし直す。**
sharp は hp/001 側にあるのでそちらの node_modules を使う。

```bash
cd ../../hp/001
NS=../../private/name-shishu node -e "
const sharp=require('sharp'),fs=require('fs'),ns=process.env.NS;
sharp(fs.readFileSync(ns+'/public/ogp.svg'),{density:144}).resize(1200,630)
  .png({compressionLevel:9}).toFile(ns+'/public/ogp.png').then(i=>console.log(i.width+'x'+i.height));
"
```

`density:144` で2倍に描いてから 1200x630 へ落としている（文字の縁が荒れないため）。

**貼る前に一度キャッシュを踏ませる。** 各SNSは取得した内容を数日〜1週間持つので、
差し替えた直後は古いままカードが出る。
LinkedIn は [Post Inspector](https://www.linkedin.com/post-inspector/)、
X は [Card Validator](https://cards-dev.twitter.com/validator)、
Facebook は 共有デバッガー に URL を入れて取り直させる。

## イラストの出どころ

トップの「こんなお悩みはありませんか？」の人物3点は **ソコスト**（https://soco-st.com/）。
**商用可・クレジット表記不要・色変更とトリミング可**（規約 https://soco-st.com/guide ）。

| ファイル | 元の作品 | 色 |
|---|---|---|
| `public/illust/worry-1.svg` | https://soco-st.com/16600 （腕を組んで困っている女性） | `#FCDC4A`（既定の黄） |
| `public/illust/worry-2.svg` | https://soco-st.com/13217 （腕を組んで困っている男性） | `#FCDC4A`（既定の黄） |
| `public/illust/worry-3.svg` | https://soco-st.com/17029 （パソコンの前で悩んでいる男性） | `#FCDC4A`（既定の黄） |

**3点とも同じ色で通す。** 1点だけ別の色にすると、並べたときにそこだけ浮く。

**規約で画像への直リンクが禁止されている。** 必ずダウンロードして `public/` に置く。
**トリミングはしない。** ソコストから落としたファイルをそのまま置き、枠の高さだけ CSS で
揃えて `object-fit: contain` に任せる（吹き出しや渦も含めて全身を出す）。

**素材によっては服の色を変えられない。** 27188 / 27151 は色替えの対象が髪だけで、
服と肌が同じクラス（`fill:#fff`）なので、服を緑にすると顔まで緑になった。
差し替えるときは、色を当てたい部分が独立しているか先に確かめる。

**吹き出しの大きい素材は選ばない。** 横長の雲が入ると人物が小さくなり、
3枚並べたときに大きさが揃わない（27188 / 27151 を 18614 / 17029 に差し替えた）。
**著作権はソコスト側にある。** 素材の再配布・素材集としての利用・AI学習への利用は不可。

## 有料掲載を1店足す（2026-09-28・2プラン化 2026-09-30）

| | 対象 | 中身 | 料金（税込） | `plans.kind` |
|---|---|---|---|---|
| 無料 | **こちらが自主的に載せた店** | **ネット上の公開情報だけ**（分からない欄は「確認中」） | 0円 | 行なし |
| **基本掲載** | **掲載のご依頼を受けて載せる店** | 基本情報を**店が自分で記入できる**（決まった欄の中だけ。自由記入にしない） | **年6,000円** | `basic` |
| **充実掲載** | どちらの店でも | 基本情報＋写真・紹介文・市区/県ページの PR 枠 | **年9,800円** | `full` |

- **どちらのプランも「PR」を付ける**（社名横と一覧）。PR 枠と「お店から」欄は充実掲載だけ
- **差別化の軸（2026-10-01）：無料＝ネットの情報だけ／基本＝店が基本情報を埋められる／充実＝さらに写真・紹介文・PR 枠。**
- **料金表は充実掲載から外した（2026-10-01・本人決定）。** 商品や内容で値段が変わり、表にすると不正確になる。
  `plans.prices` の列と型は残してあるが画面には出さない。料金の目安は基本情報の「料金の目安」欄で足りる
  基本掲載から「PR」を外す案も出たが、お金をもらって店が書く内容なのでステマ規制に当たる。**PR は付けたまま**（本人決定）
- **店向けの入口は `/listing/`（掲載のご案内）。** 基本と充実の**2段だけ**並べ、充実掲載だけの項目に★を付ける。
  **無料の段は書かない**（書くと「他の店は無料」と言うことになる）。**料金も出さない**（問い合わせ後に個別に案内）。2026-10-01 本人決定
- **店ページには★の空き枠（写真・紹介文）を出す**（充実掲載の店には出さない・`Pr.tsx` の `PrEmpty`）。
  2026-10-01 本人決定：目立ったほうが店が載せたくなる。最初は1行だけにしていたのを変えた。文言は「まだ載せていません」で、有料・無料とは書かない
- 掲載のご案内のボタンは `#contact-listing` で、フォームが「掲載・訂正のご依頼」を選んだ状態で開く
- 無料掲載の店から事実の追加（納期・郵送など）を頼まれたら充実掲載で案内する。**誤りの訂正と削除は常に無料**（利用規約 第4節）
- **画面にも依頼してきた店にも「他の店は無料」とは書かない・言わない。** 聞かれたら事実を答える

**決済はアプリに入れない。請求書を個別に送り、入金を確かめてから載せる。** 中身は掲載 DB の `plans` に1行
（金額・入金日・請求書番号も同じ行に持つ。`memo` は書き出さない）。

1. 掲載先から **紹介文・写真（提供されたものだけ）** を受け取る
2. 写真を `public/photos/<slug>-1.jpg` のように置く（**実物が無い写真はビルド時に自動で外れる**）
3. 掲載 DB の `plans` に1行足す（`kind` は basic か full）。`until` は請求した期間の最終日。写真は `photos` に `plan_id` を付けて足す
4. `node scripts/export.mjs --write` → `npm run build` → push（Vercel が本番に出す）

出るもの：店ページの「お店から」欄（写真・紹介文）と社名横の「PR」／市区・県ページの一覧の上の **PR 枠**／一覧のカードの「PR」。

- **一覧の並びは変えない。** 並べ替えは住所の有無と社名順だけ（`lib/listings.ts` の `richness`）。**写真では並べ替えない** ――
  写真は有料の中身なので、効かせると「掲載の順番は料金によって変わらない」が崩れる。9/28 に写真を並べ替えから外した
- **「PR」を消さない。** 掲載料をもらった内容なのでステマ規制で表示が要る。色も中立の灰にして、無料の店より偉く見せない
- **「有料掲載」という言葉は画面に出さない**（本人の指定）。表示は「PR」だけで足りる
- **期限切れは再ビルドで外れる**（静的書き出しなので、ビルドした日で判定する）。更新しないなら月に1回は再ビルドする
- **基本掲載の店は、期限が切れたら店ごと非掲載になる**（`plans` に basic の行がある＝依頼で載せた店。後から充実に上げても同じ）。無料で残すと更新する理由が無くなるため（2026-09-30）。こちらが自主的に載せた店は、充実掲載が切れても無料掲載に戻るだけ
- `data/plans.json` には書かない。`export.mjs` が作り直すので消える
- **お金を受け取る前に Vercel を Pro に上げる**（Hobby は商用利用不可。2026-09-28 時点で未対応）
